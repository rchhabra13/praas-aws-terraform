# AI PR Reviewer — AWS Bedrock + Terraform + GitHub Actions

Automated code review bot: every pull request gets a security/performance/best-practice review posted as a comment, generated by AWS Bedrock.

```
PR opened → GitHub Actions → fetch diff (GitHub API) → Bedrock (Amazon Nova Pro, Converse API) → review comment posted on PR
```

## Architecture

- **`github/`** — Terraform, `integrations/github` provider. Creates the private GitHub repo.
- **`infra/`** — Terraform, AWS provider. Creates:
  - GitHub OIDC provider + IAM role the Actions workflow assumes (no long-lived AWS keys stored — only the role ARN).
  - IAM policy scoped to `bedrock:InvokeModel` on the Nova Pro model ARN.
- **`.github/workflows/ai-pr-review.yml`** — runs on every `pull_request` event, assumes the AWS role via OIDC, runs the Python script.
- **`scripts/bedrock_review.py`** — fetches the PR diff via the GitHub REST API, sends it to Bedrock, posts the response as a PR comment.

## Prerequisites

- Terraform ≥ 1.6
- AWS account with Bedrock access to Amazon Nova Pro in `us-east-1`
- A GitHub personal access token in the `GITHUB_TOKEN` env var (repo scope) for the Terraform GitHub provider
- AWS credentials configured locally, for a principal with the permissions in [`infra/deployer-iam-policy.json`](infra/deployer-iam-policy.json) — this is *not* the runtime role the workflow assumes (that one is created by Terraform itself); it's what your own AWS user/role needs to run `terraform apply`. Replace the `<ACCOUNT_ID>`, `<REGION>`, `<STATE_BUCKET_NAME>` placeholders before attaching it.

## Setup (manual — run these yourself)

1. Create the GitHub repo:
   ```bash
   cd github
   terraform init
   terraform apply
   ```
2. Provision AWS infra:
   ```bash
   cd infra
   terraform init
   terraform apply -var="repo_full_name=<owner>/praas-aws-terraform"
   ```
3. Copy the `gha_role_arn` output and add it as a GitHub repo secret named `AWS_ROLE_ARN`.
4. Push this code to the repo, open a test PR, and watch the Action post a review.

## Repo layout

```
github/                      # Terraform: GitHub repo
infra/                       # Terraform: AWS OIDC, IAM role
.github/workflows/           # GitHub Actions workflow
scripts/                     # Python: diff fetch, Bedrock call, comment post
```

## Configuration

| Variable / env var | Where | Default |
|---|---|---|
| `region` | `infra` Terraform var | `us-east-1` |
| `bedrock_model_id` | `infra` Terraform var | `amazon.nova-pro-v1:0` |
| `repo_full_name` | `infra` Terraform var | *(required, no default)* |
| `AWS_ROLE_ARN` | GitHub repo secret | set manually from `terraform output gha_role_arn` |
| `BEDROCK_MODEL_ID` | workflow env | `amazon.nova-pro-v1:0` |

## Cost / cleanup

Bedrock invocations are billable. Tear down with `terraform destroy` in both `infra/` and `github/` when done.

## Design notes

- Uses the Bedrock **Converse API** instead of raw `invoke_model` — model-agnostic request/response shape, avoids per-model body-format breakage.
- Fetches the diff via the **GitHub REST API** (`Accept: application/vnd.github.v3.diff`) instead of local `git diff` — sidesteps shallow-clone "no merge base" errors, no special checkout depth needed.
- IAM policy is scoped to the specific model ARN rather than `bedrock:*` / `resource: "*"`.

## Not implemented

These were considered (and match the source tutorial's approach) but intentionally left out of this build to keep the surface area small. Add them later if needed:

- **Terraform remote state backend** — an S3 bucket + DynamoDB lock table for storing `.tfstate` remotely instead of locally. Currently state is local only.
- **CloudWatch Logs write access** — the runtime IAM role does not currently have `logs:CreateLogGroup`/`CreateLogStream`/`PutLogEvents`. GitHub Actions runner logs already cover script output; this would only matter for shipping logs into CloudWatch specifically.
